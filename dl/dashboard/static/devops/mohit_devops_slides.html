Operational Challenges

Problem Statement & Industry Motivation

Why traditional manual provisioning and single-tier monitoring fail in enterprise DevOps

⚠️

1. Configuration Drift & Snowflake Servers

Manual configurations via cloud web consoles or disparate SSH commands create untracked state alterations. Environments cannot be audited, reproduced, or recovered during disaster scenarios, leading to security vulnerabilities and software failures.

$ diff -u staging_server prod_server
- nginx 1.22.0 (unpatched)
+ nginx 1.24.0 (production baseline)
# Result: Snowflake server failure!
👁️‍🗨️

2. The Fallacy of Single-Tier Monitoring

Traditional operations often probe only public port 80 or basic hypervisor pings. However, modern architectures fail in multiple distinct tiers: an Nginx proxy can return HTTP 200/502 while the internal computation daemon is completely dead.

$ curl -I http://portal/ (HTTP 200 OK)
$ nc -zv 127.0.0.1 9010
Connection refused! Backend code runner crashed!

    Name = "int333-devops-vpc"

  }

# Zero-Touch EC2 Cloud-Init
resource "aws_instance" "web_portal" {
  ami = var.ubuntu_ami_id
  instance_type = "t2.micro"
  user_data = file("web_portal_userdata.sh")
}

Key Terraform Benefits

  • Immutable State Management: terraform.tfstate maintains cryptographic tracking of all resources.
  • Zero Configuration Drift: Any manual change made in AWS console is detected during terraform plan.
  • Reproducible Teardowns: Clean, automated cleanup with terraform destroy in < 2 minutes.
  • Cloud-Init Bootstrapping: Automatically configures Nginx, Node.js, and Python upon initial boot.

Unit III: Observability

Dual-Tier Continuous Monitoring with Nagios Core

Active daemon plugins, threshold probing, and complete visibility

🌐

Tier 1: Website Ingress

Plugin: check_http
Tests Port 80/443, evaluates HTTP 200/301 response headers, ensures fast page loads (< 500ms), and checks SSL certificate validity.

🔌

Tier 2: Code Runner Socket

Plugin: check_tcp -p 9010
Probes internal port 9010. Guarantees the backend execution engine daemon is actively accepting socket connections.

📶

Tier 3: Host Health

Plugin: check_ping
Transmits periodic ICMP echo packets to measure round-trip latency and detect packet loss across the AWS VPC.

Alert Engineering

Soft vs. Hard Alert State Lifecycle

Preventing Alert Fatigue while Guaranteeing Rapid Incident Response

🟢 OK (State 0)
All probes pass
→ Probe Fails →
🟡 SOFT STATE
Retrying (Attempts 1 & 2)
→ Max Attempts →
🔴 HARD CRITICAL
Incident Escalated!
→ Restored →
🟢 HARD OK
Auto Recovery Logged

Damping Transient Noise

Temporary network hiccups or momentary high CPU spikes trigger SOFT states, preventing engineers from being woken up by false alarms.

Hard State Escalation

When an outage persists across 3 consecutive checks (3 minutes), Nagios logs a persistent incident and triggers external alerts.
